## SOLID
Five **OOP** design principles:
- single responsibility: class does *one* thing
- open/closed: open to extension closed to modification
- liskov substitution: subclasses should be usable in place of parent without breaking things
- interface segregation: prefer small specific interfaces over one large one
- dependency inversion: depend on abstractions, not concrete implementations

## DRY
Don't Repeat Yourself: avoid duplicating logic, extract shared code instead.

## KISS
Keep it simple; don't build functionality you don't need

## OOP
**Encapsulation**: bundling data = behavior, hiding internals
- no access to private vars
**Abstraction**: exposing only what's necessary
- subclasses can build off of base methods
**Inheritance**: sharing behavior via a class hierarchy
**Polymorphism**: different classes responding to the same interface/method call differently
